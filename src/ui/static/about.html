About this system

What it is

LoanCheck is an academic prototype of a rule-based expert system for assessing eligibility for an unsecured personal loan denominated in Indian Rupees (INR). Production rules and first-order logic drive every decision; a lightweight ML classifier is built only as a comparison baseline. All policy thresholds, rate bands, and fee schedules are illustrative values stored in params/params.toml and are not derived from any real lender's credit policy. Every dataset used is either synthetic or publicly available. This is not a real lending decision.

Three possible decisions

ELIGIBLE

Eligible

The application passes all knockout checks and satisfies the policy thresholds for income, credit score, debt-service ratio, and other criteria. A recommended loan amount and indicative interest band are returned along with the full decision trace.

INELIGIBLE

Ineligible

One or more knockout rules fired — for example, an account written off, severe recent delinquency, or a credit score below the minimum floor. The trace lists every reason code that contributed to the rejection.

REFER

Refer

The application falls into a grey zone where the rules cannot give a definitive answer — for example, an unknown credit score or borderline debt-service ratio. The case is flagged for manual underwriter review with an explanation of the ambiguity.

Policy values

All numeric thresholds, interest rate bands, and fee values used by the rule engine are illustrative and are stored in a single parameter file: params/params.toml. No policy number appears directly in source code or rule text — every threshold is referenced by name. This design means that changing a parameter automatically propagates to every rule and calculation without requiring code edits.

Limits

  • Mapping effects: Input fields are mapped to internal predicates; small differences in how an applicant describes their situation can shift the outcome.
  • Synthetic data: All training and evaluation datasets are synthetic or publicly available. Distributions may not reflect real loan applicant populations.
  • No authentication: This prototype has no login, session management, or access control. It must not be used with real personal data.
  • Illustrative policy: Thresholds and rate bands are chosen to demonstrate the system, not to reflect any lender's actual credit policy.
  • No real lending decision: Output from this system has no legal or financial standing and should never be used to make or inform a real credit decision.
  • Prototype stability: The rule set, parameter values, and ML model may change between versions. Audit replay is supported but results are not guaranteed to be stable across major version updates.
